<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/schemas | schema name, field-set body, and posted master-map envelope are untrusted client input |
| session cookie → require_verified_user | the authenticated identity used for created_by/provenance must be server-resolved, never a body claim |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-05 | Elevation of privilege | POST /api/schemas, POST /master-map | high | mitigate | Both mutation routes depend on require_verified_user (401 signed-out, 403 unverified) — the gate is on the endpoint, not the UI |
| T-07-06 | Spoofing | created_by / provenance actor | high | mitigate | created_by = server-resolved user.email from require_verified_user; any client-sent created_by is ignored (mirrors AUTH-04 confirmed_by, T-06-07) |
| T-07-07 | Tampering | import_master_map augment path | high | mitigate | Import adds only; existing fields/aliases and their provenance are never overwritten or deleted (SCHEMA-03 augment-only, D-07-04) |
| T-07-08 | Tampering | posted field set / envelope field names | medium | mitigate | Routes build FieldSet via fields.loader.from_dict; from_master_map applies the same name-safety guard — no second weaker HTTP-layer check |
| T-07-09 | Denial of service | oversized field set / envelope | medium | mitigate | fields.loader.MAX_FIELDS cap (50) rejects an oversized field set before any Field/schema row is built (reused via from_dict) |
| T-07-SC | Tampering | dependency supply chain | low | accept | No new package installs — reuses existing FastAPI/pydantic + stdlib; nothing to audit |
</threat_model>
