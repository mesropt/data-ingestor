<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| imported master-map file → browser | a user-chosen .json file is parsed client-side before POST; the server re-validates (never trusts the client parse) |
| UI auth mirror → governed controls | the signed-in/verified flags gate button enablement only; the server re-checks every mutation (P1) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-14 | Elevation of privilege | promote/import buttons | medium | mitigate | Buttons gated on isGovernedActionAllowed (signed-in + verified); the server's require_verified_user is the actual authority (07-02), the UI gate is UX only |
| T-07-15 | Tampering | client-parsed master-map envelope | medium | mitigate | The browser only parses JSON for convenience; the server re-validates field names + augment semantics (07-02) — a malformed/hostile file cannot bypass the server guard |
| T-07-16 | Spoofing | vendor label as attribution | low | accept | vendor is a free-text label with no authority (D-07-06); the authoritative provenance actor is the server-resolved email, set server-side (07-03) |
| T-07-SC | Tampering | dependency supply chain | low | accept | No new npm packages — reuses existing shadcn/lucide/sonner primitives already in package.json |
</threat_model>
