<objective>
Deliver the human-facing output and the privacy dial: an explicit `--export DIR` that writes the confirmed data as CSV, `.xlsx`, and JSON — all derived from the single Phase 2 canonical table — each accompanied by a provenance manifest structurally identical to the saved profile (D-09), and blocked until the mapping is fully clear (P1: the tool never writes on its own). Plus `--headers-only` (D-10, P2): a first-class privacy branch that sends column names only, never values, to Anthropic — the feature the builder wants highlighted for the judges.

Purpose: closes the loop end-to-end from the CLI — the demo can show messy file in, clean multi-format output + audit manifest out — and makes "the more it learns / the tighter you set privacy, the less your data leaves the building" concretely true.

Output: `export/` package (writers + manifest), a `--headers-only` branch in the mapper, and `--export`/`-o` CLI wiring with the is_ready gate.
</objective>

## Phase Goal (user story)

**As a** data curator, **I want to** export a mapping I have fully cleared as CSV, Excel, and JSON with an audit manifest, and optionally run the mapper without ever sending my values off-machine, **so that** I get the exact file a scientist opens plus a provenance trail — and confidential values can stay local when I need them to.

After each task: (1) I can turn a canonical table into three files + a manifest; (2) `--export` writes them only when the mapping is clean, never on its own; (3) `--headers-only` maps without sending a single value to the API.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| confirmed mapping → written files | Export is the one place the tool writes; it must be gated on is_ready and explicit. |
| file values → Anthropic API | The 6-row sample is the confidential-value egress point; --headers-only closes it. |
| export path (-o / DIR) | A path argument controls where files land. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09 | Information Disclosure | mapper 6-row sample egress | high | mitigate | `--headers-only` sends column names only, no values (D-10); the auto-apply path already issues zero Claude calls (learning-as-privacy-control, P2). |
| T-03-10 | Tampering / Repudiation | export without a clean gate | high | mitigate | Export blocked unless proposal.is_ready (D-09/P1) and only on an explicit `--export`; the manifest records provenance (auto-applied vs fresh-Claude) and strictness as an audit trail (D-08/D-11). |
| T-03-11 | Tampering | `-o` / export DIR path argument | low | accept | Trusted local CLI operator in v1; path-traversal hardening deferred to the Phase 4 server surface (RESEARCH Security Domain). |
