## Phase Goal

**As a** data curator, **I want to** define fields, upload a messy CRO file, resolve any structural hint and yellow fields, and confirm in the browser, **so that** the tool learns the format and auto-maps the next same-source file with no Claude call.

(Derived faithfully from the ROADMAP Phase 4 Goal line — the browser define-fields → upload → resolve-hint → review → confirm → learn cycle with a server-enforced gate.)

<objective>
Extract cli.py's private, print-coupled orchestration into a new PUBLIC `service.py` that decides but never renders, so both the CLI and the coming FastAPI routes call one seam. This is the behavior-preserving refactor every later Phase 4 plan depends on. Also add the FastAPI/uvicorn/multipart backend dependencies (behind a package-legitimacy checkpoint) and a public `fields/loader.from_dict` seam so the field-sets HTTP endpoint (Plan 03) can build a validated FieldSet from a request body.

Purpose: `.claude/CLAUDE.md`'s "Public API is everything not prefixed with `_`" makes a new `api/` package importing `cli._map_one` a boundary violation; several of those functions `print()`. The service layer returns data (MapResult) or raises typed exceptions; each adapter renders its own way (print vs JSON). This satisfies the backend-logic side of API-01 (resolve_or_map), API-02 (confirm gate), and API-03 (auto-apply branch) without any new business logic.

Output: `service.py` (public functions + MapResult/typed exceptions), a refactored `cli.py` that delegates, a public `from_dict` in `fields/loader.py`, the three new deps in `pyproject.toml`, and `tests/test_service.py` proving the seam.
</objective>
