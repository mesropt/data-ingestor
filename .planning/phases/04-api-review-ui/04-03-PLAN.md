## Phase Goal

**As a** data curator, **I want to** define fields, upload a messy CRO file, resolve any structural hint and yellow fields, and confirm in the browser, **so that** the tool learns the format and auto-maps the next same-source file with no Claude call.

<objective>
Deliver the server-side confirm gate (API-02, the P1 fail-closed heart of the phase), the field-set template store + endpoints (UI-01, D-03), the inline structural-hint resolve endpoint (UI-02, D-04 — deterministic parser question only, no Claude structural enrichment on the API path per W1), and the export download endpoints. Then prove the full browser money-shot at the API level (SC4).

Purpose: API-02 is the requirement the whole "trust the numbers" principle rests on — a tampered or buggy client must not be able to persist a yellow mapping. The confirm route rebuilds a fresh domain MappingProposal from only the legitimately client-editable column choices and re-runs the exact validator, ignoring any client verdict. Field-set storage mirrors the existing ProfileStore seam exactly (D-03). The hint endpoint reuses the retained upload and returns the deterministic parser question; it makes no Claude structural-enrichment call, so no evidence-row leak vector exists on the hint path (W1).

Output: the FieldSetTemplateStore ABC + SqliteFieldSetStore, four route modules (field_sets, confirm, structural_hint, export), their wire models, and API tests including the tampered-yellow rejection and the money-shot spy.
</objective>
