## Phase Goal

**As a** data curator, **I want to** define fields, upload a messy CRO file, resolve any structural hint and yellow fields, and confirm in the browser, **so that** the tool learns the format and auto-maps the next same-source file with no Claude call.

<objective>
Deliver the Upload screen (UI-02): field-set picker, the P2 Headers-only privacy toggle, the file dropzone, and — the D-04 centerpiece of this slice — the inline structural-hint form that appears in the same flow when the parser is unsure, honoring the headers-only privacy guard in its evidence preview. After this plan a user can upload a messy file and, when structure is ambiguous, resolve it inline and get a mapping back.

Purpose: this connects the browser to /api/upload and /api/structural-hint/resolve (Plans 02/03). The hint UX is inline (never a modal/wizard) per D-04, and the evidence preview must show no cell values under headers-only (P2, CR-01) — mirroring the server-side guarantee on the client render.

Output: the Upload screen, its subcomponents (UploadDropzone, FieldSetPicker, HeadersOnlyToggle, StructuralHintPanel), the upload state machine, its vitest suite, and the api.ts upload/resolveHint calls.
</objective>

| T-04-17 | Tampering | client sends stale/absent upload_token to resolve-hint | low | accept | The server looks up the retained upload by token; an unknown token is a clean 404, no client escalation possible |
