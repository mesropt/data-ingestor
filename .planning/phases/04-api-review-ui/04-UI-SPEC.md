# Phase 4 — UI Design Contract

> Visual and interaction contract for the AssayIngest browser Review UI — the demo's centerpiece. Generated by gsd-ui-researcher from locked decisions D-01/D-02/D-03/D-04 in `04-CONTEXT.md`. The aesthetic direction is DECIDED (clean clinical/lab, light-primary, restrained blue-green accent, amber-visible uncertain cells) — this document turns it into implementable tokens, components, and states. Verified by gsd-ui-checker; referenced by gsd-planner and gsd-executor as the visual source of truth.

**No frontend exists yet** — this is a from-scratch Vite + React build (per `.claude/CLAUDE.md` stack). No `components.json`, no prior tokens, no prior components. This contract establishes the system.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (Radix primitives + Tailwind CSS) |
| Preset | Not interactively initialized (autonomous/yolo project mode — no live user session to paste a ui.shadcn.com preset string). Planner/executor runs `npx shadcn@latest init -d` (non-interactive defaults: New York style, neutral base) then **replaces every generated CSS variable** with the values in the Color section below. Do not ship the generated zinc/slate defaults — they contradict D-01. |
| Component library | Radix primitives via shadcn: `Select`, `AlertDialog` (destructive confirms), `Switch` (headers-only toggle), `Tabs` (top nav), `Tooltip` (disabled-button reason), `Toast`/`Sonner` (confirm/error feedback), `Popover` (manual-dropdown fallback if not a plain `<Select>`) |
| Icon library | `lucide-react` (ships with shadcn, has every icon this contract needs: `CheckCircle2`, `AlertTriangle`, `FlaskConical`, `Sparkles`, `RefreshCw`, `Trash2`, `ChevronDown`, `Sun`, `Moon`, `UploadCloud`, `FileWarning`) |
| Font | Display/body/label: **Inter** (variable, self-hosted — bundle the woff2 in the app, do NOT load from a CDN; a live demo cannot depend on network availability). Data/mono role: **JetBrains Mono** (self-hosted, subset to Latin + digits to keep bundle small). |

**Why self-hosted fonts, not Google Fonts CDN:** the entire pitch is a live 3-minute demo (ROADMAP Phase 5) — a CDN hiccup mid-recording is an unforced risk. Bundle both font files under `frontend/public/fonts/` and reference via `@font-face`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, chip internal padding (vertical) |
| sm | 8px | Compact element spacing, chip internal padding (horizontal), chip-to-chip gap |
| md | 16px | Default element spacing, field-row padding, form-field vertical rhythm |
| lg | 24px | Section padding, gap between the source-columns pane and the target-fields pane |
| xl | 32px | Layout gaps, screen-level top/bottom padding |
| 2xl | 48px | Major section breaks (e.g. between "Define Fields" toolbar and the field list) |
| 3xl | 64px | Page-level spacing (rare — top-level screen margins on wide viewports) |

**Exceptions:**
- Confidence chip and alternative-column chip minimum clickable height: **32px** (below the general 44px touch-target guideline) — this is a desktop-first, mouse-driven data-review tool; the demo runs on a laptop, not a touch device. Documented exception, not an oversight.
- Sticky confirm-gate footer height: **64px** fixed (matches 3xl for visual weight as the single most important control on the Review screen).
- Amber-cell left border: **4px** solid (xs token, used structurally as a state indicator, not spacing).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display | 28px | 600 (semibold) | 1.2 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Body | 16px | 400 (regular) | 1.5 |
| Label / Mono-data | 13px | 400 (regular); 600 for emphasis (e.g. field names, chip percentages) | 1.4 |

Exactly 4 declared sizes (28/20/16/13), exactly 2 declared weights (400/600) — per contract discipline. The **mono role** reuses the 13px Label size with `font-family: 'JetBrains Mono'` instead of Inter; applied specifically to: source-column names, sample cell values in previews, confidence percentages, dates, row/column counts. Apply `font-variant-numeric: tabular-nums` to ALL numeric text project-wide (including Inter body text showing counts like "3 of 7 fields resolved") — this is the one typographic signature that reads as "clinical/lab" per D-01, independent of the mono font.

**Usage map:**
- Display (28/600): screen titles — "Define Fields", "Upload File", "Review Mapping".
- Heading (20/600): section headers within a screen — "Source Columns", "Target Fields", panel titles inside dialogs.
- Body (16/400): all prose — Claude's reasoning text, validator notes, empty/error states, form labels' helper text, button labels.
- Label/Mono (13/400 or /600 semibold): table headers, chip contents, badges, timestamps, field metadata (type/unit/required badges), the entire structural-hint preview grid.

## Color

Two full themes are declared (light primary, dark secondary) per D-01 — "support both themes at the token level even though light is primary." **Semantic state colors (success/uncertain/destructive) are deliberately distinct hues from the interactive accent** — this is load-bearing: on the Review screen, a field must never be ambiguous between "this is a clickable accent element" and "this is a state signal."

### Light theme (primary)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F9F8` | App canvas / page background |
| Secondary (30%) | `#FFFFFF` (cards, table panes, dialogs) + `#EDF2F1` (top nav bar, sticky footer) | Cards, side-by-side panes, nav, sticky confirm-gate footer |
| Accent (10%) | `#0F766E` (teal-700) | **Reserved for:** primary CTA background ("Confirm & Save Mapping", "Save Field Set", "Upload & Map"), active nav-tab underline, input focus ring, text links, selected alternative-chip border+fill, the "Auto-mapped from saved profile" banner accent bar, app logo/wordmark |
| Success / clear-field | `#16A34A` (green-600) | Green check icon + subtle left-border tint on a **clear** (resolved) field row only. NEVER used for buttons or links — that would collide semantically with accent. |
| Uncertain / amber | `#F59E0B` border, `#FEF3C7` background, `#92400E` text/icon | Amber-highlighted cell/row for a `needs_confirmation` field: full-row tinted background, 4px left border, warning icon, reasoning text |
| Destructive | `#DC2626` (solid button/icon), `#FEE2E2` (hover/bg), `#991B1B` (text on light bg) | Delete field, delete template, delete saved profile — ONLY |
| Border / divider | `#E2E8E6` | Card borders, table row dividers, input borders |
| Text primary | `#0F172A` | Headings, body copy |
| Text secondary/muted | `#475569` | Helper text, timestamps, disabled labels |
| Text disabled/placeholder | `#94A3B8` | Placeholder text, disabled button label |

Accent reserved for: primary CTA buttons, active nav-tab indicator, focus rings, text links, selected chip, auto-applied-profile banner accent — **never** for success/clear-state indication (that is green) and **never** for destructive actions (that is red).

## Screens & States

Every screen below maps to its requirement(s). Loading/empty/error states are declared for each — the executor should not have to invent them.

### 1. Define Fields (UI-01)

**Layout:** Single-column form area, max-width ~840px, centered on the canvas. `FieldSetToolbar` pinned at the top (Load-template dropdown, field-set name input, "Add Field" button, "Save Field Set" primary CTA). Below it, a vertical stack of `FieldEditorRow` components, one per declared field.

**FieldEditorRow fields (maps directly to `fields/models.py::Field`):**
- Name (text input, required, 64-char limit per `_MAX_NAME_LENGTH`)
- Description (text input, optional)
- Type (select: `none` / `number` / `integer` / `date` / `text` — matches `FIELD_TYPES`)
- Allowed values (tag/chip input, comma-or-enter to add, only shown meaningfully once a type is chosen; optional)
- Unit (text input, optional — shown for any type, most relevant for `number`)
- Required (switch, default ON, matches `Field.required` default `True`)
- Min / Max (two number inputs, shown only when Type = `number` or `integer`)
- Date format (text input with placeholder `e.g. %Y-%m-%d`, shown only when Type = `date`)
- Delete icon button (`Trash2`, destructive-colored on hover) at the row's trailing edge

**States:**
- Empty: see Copywriting Contract. Illustration-free — a single centered icon (`FileWarning` or similar, muted) + heading + body + "Add Field" CTA.
- Loading (loading a saved template): skeleton rows (3 gray pulse bars) in place of `FieldEditorRow`s, toolbar disabled.
- Error (template failed to save/load): inline `Alert` (destructive-tinted) above the toolbar with the server's consequence-first message; form state preserved, nothing is lost.
- Field-cap warning: if the user is at or near `MAX_FIELDS` (50), "Add Field" becomes disabled with a tooltip: "Field sets are capped at 50 fields."

### 2. Upload (UI-02)

**Layout:** Single-column, max-width ~720px, centered. Top-to-bottom: `FieldSetPicker` (select which saved field set this upload maps to), `HeadersOnlyToggle` (with helper text, see Copywriting), `UploadDropzone`, then — conditionally — the `StructuralHintPanel` (D-04) inline below the dropzone when the server returns a `StructureQuestion`.

**UploadDropzone states:**
- Idle: dashed border card, `UploadCloud` icon, "Drag a CSV or Excel file here, or click to browse," accepted extensions listed in Label/mono text (`.csv .xlsx .xls`).
- File selected: dropzone collapses to a compact file chip (filename, size, remove `×`), "Upload & Map" CTA becomes enabled.
- Uploading/parsing: CTA shows an inline spinner + "Mapping…" label; dropzone and field-set picker disabled.
- Error: red-bordered dropzone + inline destructive `Alert` with the consequence-first message (see Copywriting "file cannot be read as a table").

**StructuralHintPanel (D-04 — inline, not modal, not a wizard step):**
- Renders directly below the dropzone in the SAME upload flow, pushing the layout down — never a `Dialog`/overlay.
- Header: "Help us find the table" (Heading 20/600) + the `StructureQuestion.reason` text (Body 16/400).
- Evidence preview: a small read-only grid (`evidence_rows`, capped ~5 rows), monospace (13px), zebra-striped rows, inside a bounded card with its own horizontal scroll if wide.
  - **When `--headers-only` is ON:** the grid renders NO cell values — only column count and row count, per P2 (Copywriting: "Cell values hidden — headers-only mode is on"). This applies even though the hint evidence path is a separate code path from the main mapper call (Phase 3 CR-01 fix) — the UI must honor the same toggle state for both.
  - A row in the grid is clickable to set `header_row_index` directly (click-to-select is friendlier than a bare number stepper) when that is the dimension in question.
- Answer controls, shown only for the dimensions actually in question (mirror whichever `StructuralHint` fields are null/relevant): `header_row_index` (number stepper OR row-click, above), `sheet_name` (select, if multiple sheets), `delimiter` (select: comma/semicolon/tab), `decimal_separator` (select: point/comma).
- `proposal` (the tool's best guess) pre-fills the controls but is never auto-applied — the human must submit.
- If `answerable_by_hint` is `False` (an unsupported table shape): render the reason and evidence only, NO answer controls, with guidance copy: "This file's structure ({table_shape}) isn't supported yet. Reshape it to one row per record, or try a different file." — never imply an answer will help when it can't.
- CTA: "Use This and Re-parse" (accent primary), re-submits the upload with the hint attached.

### 3. Review (UI-03/04/05 — the centerpiece)

**Layout:** Full-width working area (not centered/narrow like the other screens — this is the money shot and needs room). Structure top to bottom:
1. Screen title ("Review Mapping") + file name + field-set name (Label/mono, muted) + `ProfileAppliedBanner` (only when API-03 auto-applied — see below).
2. The two-pane side-by-side table region (bounded height, its own scroll — see Layout & Responsive).
3. Sticky `ConfirmGate` footer (always visible, pinned to viewport bottom within the app shell).

**Two-pane region:**
- **Left pane — Source Columns** (~32% width, `Secondary` surface `#FFFFFF`, `Heading` "Source Columns"): a read-only vertical list of every `source_column` name from the parsed table, mono/Label styling, each with 1-2 truncated sample values shown as small muted chips beneath the name (omitted entirely under `--headers-only`, replaced with a single muted note "values hidden — headers-only mode"). Purely a reference pane — nothing here is clickable.
- **Right pane — Target Fields** (~68% width, `Heading` "Target Fields"): one `FieldRow` per `FieldMapping` in `MappingProposal.field_mappings`, in the order the user declared their fields.

**FieldRow — clear state (`is_clear == True`):**
- Left accent: thin 4px `#16A34A` (success) border, subtle `#F0FDF4`-tint background (very light green wash, NOT the amber wash).
- `CheckCircle2` icon (success color).
- Field name (Body 16/600).
- Mapped source column (Label/mono 13px), confidence badge (Label/mono, e.g. "94%", tabular-nums).
- Reasoning collapsed by default behind a "Why?" text-button disclosure (Body 16/400 when expanded) — clear fields don't need to shout their reasoning; amber fields do (below).

**FieldRow — uncertain/amber state (`needs_confirmation == True`):**
- Full-row amber wash `#FEF3C7`, 4px `#F59E0B` left border — visible at rest, no hover needed (D-01 hard requirement — never hide the reason behind hover).
- `AlertTriangle` icon (`#92400E`).
- Field name (Body 16/600) + "Needs review" `Badge` (amber-toned).
- **Claude's reasoning shown inline, always visible** (Body 16/400, `#92400E` on the amber wash), prefixed with a small `Sparkles` icon to mark it as Claude's voice.
- **`validator_note`, when present, shown as a visually distinct sub-line** (separate from Claude's reasoning text, per the domain model's own "tool note kept separate" convention) — prefixed with a `FlaskConical` icon to mark it as the deterministic no-LLM validator's voice, not Claude's. If `validator_note` is `None`, this sub-line is omitted entirely (never render "No validator note").
- **Ranked-alternative chips row** (D-02a): one `ConfidenceChip` per `ColumnCandidate` in `alternatives`, each reading `{source_column} · {confidence%}` in mono/tabular-nums, laid out with `sm` (8px) gaps. Clicking a chip resolves the field to that column and clears amber.
- **"Accept" button** (D-02b): secondary/outline button, accent-colored label, text "Accept" — takes Claude's top proposal (`source_column` as already set on the `FieldMapping`) as-is and clears amber.
- **Manual dropdown** (D-02c, fallback): a `Select` populated with EVERY `source_column` from the parsed table (not just the alternatives) — placeholder "Choose a different column…". Selecting any option resolves the field to that column and clears amber. This is the guaranteed escape hatch when the correct column isn't among Claude's ranked alternatives.
- Resolving via (a), (b), or (c) transitions the row to the clear state with a brief (150ms) background-color transition — no layout jump, no modal, no page navigation.

**`inferred_value` display:** when `source_column` is `None` but `inferred_value` is set (a value inferred with no matching column — MAP-02), the row still renders in amber (per `needs_confirmation`) with the inferred value shown in place of a source-column name, mono-styled, prefixed "(inferred)" in Label/muted text — so it is never confused with a genuine column match.

**ProfileAppliedBanner (API-03, the second-half of the money shot):** rendered once, above the two-pane region, only when the server indicates auto-apply occurred. Accent-toned banner (not success-green, not amber — this is a *provenance* signal, distinct from field-clear state): `RefreshCw` icon, copy per Copywriting Contract, "Not right? Edit anyway" link that does nothing structurally — the FieldRows underneath are simply already all in the clear state and remain fully editable via the same three D-02 controls if the curator disagrees.

**ConfirmGate (sticky footer, UI-05):**
- Left side: progress text "{count of clear fields} of {total fields} resolved" (Label, tabular-nums).
- Right side: "Confirm & Save Mapping" primary CTA.
- **Disabled** (grayed, `cursor: not-allowed`, `Tooltip` on hover/focus with the disabled-tooltip copy) while `MappingProposal.is_ready` is `False` (i.e., ANY field amber) — this exactly mirrors `is_ready`/`needs_confirmation` from `domain/models.py`, not a separately-computed client heuristic.
- On click, calls the confirm endpoint. **The server independently re-runs the gate (P1)** — if it rejects (a bug, a race, a stale client state), the UI shows the "confirm rejected by server gate" error state (Copywriting) and does NOT proceed to the export/success UI. The client-side disabled state is a UX convenience; the server response is the only thing that ever unlocks Export.
- On success: footer transitions to show the `ExportBar` (Export CSV / Export Excel / Export JSON / Download Manifest) plus the confirm success toast.

**Loading state (Review screen):** while the upload/map call is in flight, the two-pane region shows skeleton `FieldRow`s (gray pulse bars, no color state yet) and the footer CTA is disabled with spinner label "Mapping…".

**Error state (Review screen):** if mapping itself failed (not a per-field issue — an API/Claude call failure), the two-pane region is replaced by a centered destructive `Alert` (see Copywriting "mapping call fails") with a "Try Again" secondary button that re-triggers the same upload.

### 4. Confirm + Learn (UI-06 — the second half of the demo money shot)

Not a separate screen — this is the Review screen's post-confirm state (`ExportBar`, above) PLUS the next Upload of a same-signature file. On that second upload, the Review screen loads directly into the `ProfileAppliedBanner` state with **zero amber rows** — the visible proof of the learning loop. No separate "Profiles" screen is required by the requirements, but a minimal **Profiles list** (accessible from `AppShell` nav, "Profiles" tab) is worth having for the destructive delete-profile flow declared in the Copywriting Contract; it is a simple read-only list (source label, field set, signature short-hash in mono, saved date) with a `Trash2` delete icon per row triggering the destructive `AlertDialog`.

## Layout & Responsive Behavior

- **Desktop-first**: the Review screen's side-by-side pane is the reason this tool exists visually; it is not designed to gracefully collapse into a single mobile column. Below **1024px** viewport width, the two-pane region does **NOT** restack vertically — instead the inner grid holds a `min-width: 960px` and the region itself becomes a horizontally-scrolling container (`overflow-x: auto`), while the **page body itself never scrolls horizontally** (`overflow-x: hidden` on `<body>`/`AppShell`). This satisfies the explicit contract: "horizontal scroll container, never body scroll."
- The two-pane region also has a bounded **vertical** height: `max-height: calc(100vh - {AppShell top bar height} - {ConfirmGate footer height})`, so its own content scrolls vertically inside that box while the sticky footer (`ConfirmGate`) and top bar remain permanently visible — the confirm button must never require scrolling to find.
- Define Fields and Upload screens are single-column, centered, and reflow naturally at any width (they hold forms, not a wide table) — no special-casing needed there.
- All interactive targets respect the 32px minimum documented in the Spacing exceptions; standard buttons/inputs use the default browser/shadcn sizing (40-44px) which already satisfies broader accessibility guidance.
