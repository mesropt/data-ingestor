## Phase Goal

**As a** data curator, **I want to** define fields, upload a messy CRO file, resolve any structural hint and yellow fields, and confirm in the browser, **so that** the tool learns the format and auto-maps the next same-source file with no Claude call.

<objective>
Deliver the Review screen — the demo's centerpiece (UI-03/04/05) — and close the loop with confirm/learn and the visible auto-apply money-shot (UI-06). Side-by-side source/target panes, amber uncertain rows with Claude's reason + validator_note + ranked chips + Accept + manual dropdown (D-02), a sticky confirm gate mirroring the server gate, export after confirm, and the ProfileAppliedBanner that makes the "0 Claude calls" second upload visible.

Purpose: this is where "Claude proposes, human disposes" becomes tangible and where 30% of judging (a compelling, cool-to-watch demo) is won. The client gate is a UX mirror; the server (Plan 03 /api/confirm) is authoritative (P1) — the UI must handle a 422 rejection without unlocking export. The money-shot's provable API test already exists (Plan 03); this plan makes it visible and adds a human-verify checkpoint for the Phase 5 video.

Output: the Review screen + subcomponents (ReviewTable, FieldRow, ConfidenceChip, ConfirmGate, ExportBar, ProfileAppliedBanner), the review state module + vitest, and a browser money-shot checkpoint. (Profiles management — a list-all / delete screen — is DESCOPED for v1 per W2: it is neither a requirement nor a success criterion and would require a new untested ProfileStore.delete/list-all + routes. The learning loop is demonstrated by the auto-apply banner on the second same-signature upload, which stays.)
</objective>
