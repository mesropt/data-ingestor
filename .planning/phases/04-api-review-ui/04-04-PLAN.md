## Phase Goal

**As a** data curator, **I want to** define fields, upload a messy CRO file, resolve any structural hint and yellow fields, and confirm in the browser, **so that** the tool learns the format and auto-maps the next same-source file with no Claude call.

<objective>
Scaffold the Vite + React + shadcn frontend, install the D-01 design system (tokens, fonts, AppShell with tab nav + theme toggle), and deliver the first browser screen: Define Fields (UI-01) — create/edit a field set and save/load it as a named template against the Plan 03 field-sets endpoints. After this plan a user can, in the browser, build a field set and persist it for reuse.

Purpose: this establishes the frontend system the review screen (Plan 06) builds on. The aesthetic is DECIDED (04-UI-SPEC.md, D-01) — this plan turns the tokens/typography/spacing contract into a real shadcn theme and the field-authoring form into the shape the upload endpoint expects. No new backend logic.

Output: the Vite app skeleton, the shadcn theme replacing generated defaults, self-hosted Inter + JetBrains Mono, AppShell + ThemeToggle, an api.ts client + shared types, the DefineFields screen with FieldEditorRow/FieldSetToolbar, and vitest tests for the field-set editor state.
</objective>
