<objective>
Deliver SHEET-01 and SHEET-04's backend: a multi-sheet workbook asks WHICH SHEETS, shows what the tool knows about each (headers, rows, signature, status, ranked Schema proposals with their coverage), and turns the human's answer into N independent datasets.

Purpose: today a multi-sheet workbook either asks a single-select "which sheet" structural question or **silently discards** every other sheet (meridian's LEGEND, right now). Both are the guesses this phase exists to kill.

**No merge, anywhere (D-11-07/D-11-08).** SHEET-02 is struck from the PRODUCT, not deferred. N selected sheets produce N INDEPENDENT datasets — each with its own Schema, its own mapping, its own amber gate, its own export. Nothing in this plan may combine records across sheets, and no "merge later" affordance may be left behind.

Architecture (D-11-20, D-11-21 — both settled by research, do not re-litigate; they SUPERSEDE D-11-01's trigger wording and defuse D-11-11's cost warning):
- The manifest sits **above `parse()`**. `parse()`, `_resolve_sheet`, `rank_sheets`, `SheetRanking` are NOT TOUCHED. Each selected sheet is then parsed with `parse(path, sheet=X)`, which short-circuits ranking (`table.py:359-367`) and runs the full per-sheet gate chain — that is how SHEET-04 comes for free, and why each sheet resolves its own date order for itself (D-11-09: the old cross-sheet-disagreement clause is moot and must NOT be built).
- The run group is **a group id owning N ORDINARY `upload_token`s** (Option A). This changes ZERO of `service.confirm`, `service.export`, `_is_review_ready`, the `pending_uploads` round-trip, `GET /api/export/{run_id}/{fmt}`, `MappingResponse`, or `date_format.py`. Do **not** widen `UploadEntry` to hold N tables — research proved that breaks eight call sites.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/sheets/resolve | `sheet_name` and `schema_name` are untrusted and reach `parse()` and the Schema store |
| client → POST /api/upload (multi-sheet branch) | An arbitrary workbook drives a new server-side manifest path |
| retained temp file → N members | One file, N lifecycles — a shared path is a use-after-unlink |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-22 | Tampering | client-supplied `sheet_name` reaching `parse()` | high | mitigate | Validate every selection against the SERVER-RETAINED manifest before any filesystem access; 422 naming the consequence, never a `ValueError` surfacing as 500 (Pitfall 6) |
| T-11-23 | Elevation of privilege | unauthenticated drive-to-completion of a retained upload | high | mitigate | `Depends(require_user)` on `/api/sheets/resolve` (D-10-13) — closing `/api/upload` alone would leave the continuation open |
| T-11-24 | Denial of Service / data loss | one member's resolve unlinking another member's temp file | high | mitigate | Per-member `shutil.copyfile`; each member owns its own path, so every existing unlink and the registry's eviction-unlink stay correct unchanged |
| T-11-25 | Spoofing | a client-supplied token or group id becoming server state | medium | mitigate | The `group_id` and every member token are server-minted `uuid4`; the client only ever chooses among server-retained options (T-08-08) |
| T-11-26 | Information disclosure | headers exposed under `headers_only` | low | accept | A header is not a cell value (D-10-05). The manifest shows headers and sheet names; it carries no `example_values` equivalent, so no redaction hook is needed. |
| T-11-27 | Information disclosure | N members ⇒ N persisted `pending_uploads` rows | medium | accept | Each rides the existing TTL and is purged by its own `registry.pop` at confirm; unconfirmed members expire on the same TTL as today's single upload |
| T-11-SC | Tampering | package installs | high | accept | Zero packages installed (`shutil` is stdlib). |
</threat_model>
