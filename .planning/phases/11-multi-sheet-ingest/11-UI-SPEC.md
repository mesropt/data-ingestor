# Phase 11 — UI Design Contract

> Visual and interaction contract for the two new surfaces of multi-sheet ingest: the **sheet-selection panel** (the 5th `kind: "sheet_question"` response arm) and the **tabbed Review over N independent datasets** (`kind: "sheet_group"`, D-11-10) — plus the ruling on how row provenance (`__source_sheet`, D-11-12) surfaces in Review. Generated by gsd-ui-researcher from `11-CONTEXT.md` (D-11-02/03/06/08/10/12/16/19/20), `11-RESEARCH.md` (Pattern 5/6, Pitfalls 5/8), ROADMAP Phase 11 success criteria, and `10-UI-SPEC.md`. **This is an EXTENSION of the existing design system, not a new one** — every token, type role, icon convention, and component idiom shipped through Phase 10 is binding and reused verbatim. This phase introduces **zero new hex values, zero new type roles, and exactly one new shadcn official primitive (`checkbox`)** — declared in Registry Safety below.

**Product principles this design must make LEGIBLE, not merely satisfy** (from `11-CONTEXT.md` and the phase brief):
- **The tool proposes, the human disposes** — the sheet screen is ALWAYS shown for a multi-sheet workbook; the proposal is pre-filled, never auto-applied (D-11-06). No threshold, no "confident enough to skip the screen".
- **Never guess silently** — a zero-coverage sheet is proposed as *skip*, a tie is shown as a tie, a gate-failed sheet appears in the manifest *marked*, never dropped.
- **Show the reasoning, not just the verdict** — the coverage that produced each proposal ("6/7 canonical fields matched", and *which* field matched *which* header) is visible on the screen, because the human is being asked to check the tool's proposal and cannot check what is not shown (D-11-03, the builder's own words).

## Registry Safety

| Registry | Blocks Used | Safety Gate |
|----------|-------------|--------------|
| shadcn official | Existing installs reused unchanged: `button`, `input`, `label`, `card`, `alert`, `badge`, `select`, `tabs`, `tooltip`, `skeleton`, `sonner`. **One new install: `checkbox`** (official registry) | not required (official registry; consistent with `04-UI-SPEC.md`'s vetting of the official source) |
| Third-party | none | not applicable |

**Why `checkbox` and not zero installs:** the manifest is a true multi-select ("the human ticks which sheets to ingest" — SHEET-01's literal shape). `Switch` (installed) means "a mode is on/off"; a selected-card click pattern conflicts with the embedded per-sheet `Select` (a click intended for the dropdown toggles the selection). A visible checkbox is the one control whose state IS the answer to the question being asked. No other primitive is added: the Review member tabs reuse the installed `tabs`; the coverage detail is plain conditional JSX (the `StructuralHintPanel`/`ReconcilePanel` inline-block pattern, no `Accordion`/`Collapsible`). If the executor wants any richer primitive, it MUST come back through this contract first.

## Discretion Calls (Claude's Discretion in `11-CONTEXT.md`, resolved here)

### 1. Sheet-selection layout: one card per sheet, one submit — the `DateFormatQuestionPanel` shape, not a table

**Decision:** the sheet question renders as **one inline `Card` below the dropzone** (same slot, same `max-w-[720px]`, same "one panel at a time, blocks Review until resolved" rule as the other three question panels), containing **one bordered block per sheet** (`rounded-lg border border-border p-3` — `ReconcilePanel`/`DateFormatQuestionPanel`'s exact per-item block) and **one submit for all sheets at once**. This is D-11-02's own precedent ("the pattern to copy is `date_question`") carried into the visual layer: `DateFormatQuestionPanel` is the multi-item/single-submit sibling, and the new panel is its structural twin with a checkbox and a `Select` where the date panel has two option buttons. A data-grid/table layout was rejected: each sheet carries too much per-item reasoning (headers, coverage pairs, tie/skip notices) to fit a row, and a table would push the reasoning into tooltips — hiding exactly what D-11-03 orders shown.

**Per-sheet block anatomy, top to bottom (md 16px rhythm):**
1. **Selection row** — `Checkbox` + sheet name (mono, 600) + "{row_count} rows" (mono, muted) + status badge when not `ok`. The whole row is the checkbox's click target (32px min height).
2. **Detected headers** — label + the sheet's headers as mono chips (existing `Badge`/chip idiom from the alias list), wrapping. Shown in full; headers are never redacted under headers-only.
3. **Proposal + coverage** — the coverage line per Copywriting Contract with its source suffix, then the matched pairs ("`{field} ← {header}`", one mono line each) and the "Not matched:" remainder, always visible, not behind a disclosure. This block is the phase's reason to exist — it does not collapse.
4. **Schema select** — "Schema for this sheet" + `Select` over the governed Schemas. Pre-selection precedence: scorer's proposal → the Upload dropdown's Schema if one was chosen (D-11-16 default) → empty. A **tie leaves it empty** with the amber tie notice above it; a **zero-coverage** sheet leaves it empty with the skip line and the checkbox unticked.

**Pre-selection states (D-11-06, verbatim):** proposal exists → ticked + Schema pre-selected; zero coverage → unticked + no Schema + skip line; tie → ticked + no Schema + amber tie notice; gate-failed (`no table found` / `unsupported shape`) → unticked + muted badge, but **still present and still tickable** — the human may insist, and the failure then surfaces as that member's own structural question in its Review tab (SHEET-04: marked, never dropped, never disabled away). `header unclear` → unticked + amber badge + the helper line, tickable for the same reason.

**Submit gating (fail-closed, mirrors the wire's empty-selections 422):** disabled at 0 ticked, and disabled while any ticked sheet has no Schema chosen — with the specific blocked reason shown (Copywriting Contract), reusing the dropzone's existing disabled-reason idiom.

### 2. Tabbed Review: member tabs that never remount, gates that never merge

**Decision:** resolving the sheet question lands on **Review with a member-tab strip** above the existing header block — the installed `Tabs` primitive, one `TabsTrigger` per member labeled with its sheet name (mono) plus a status indicator: amber "{n} to resolve" badge (unresolved amber fields), amber dot (a pending structural/date question), or the green check (confirmed). **Every `TabsContent` uses `forceMount` and is hidden when inactive** — 11-RESEARCH Pitfall 8 is a design requirement here: `Review.tsx` holds amber resolutions in local state, and a remounting tab silently destroys a curator's work, which is a correctness failure, not a UX nit.

**Inside each tab is the existing Review, whole and unweakened:** its own `ReviewTable`, its own escalation-summary line, its own vendor input, its own 4-tier `ConfirmGate` (64px footer, per member — the gate is per-dataset by D-11-08 and is never aggregated), its own `ExportBar` after confirm. A member whose wire arm is still `structural_question` or `date_question` renders `StructuralHintPanel` / `DateFormatQuestionPanel` **verbatim inside its tab** in place of the table (the recursive-arm shape from 11-RESEARCH Pattern 6); on resolve, the tab swaps to the normal Review content in place.

**Group export:** a single "Download All ({n} datasets)" action (accent, `FileArchive` icon) in a slim bar above the tab strip — enabled only when **every** member is confirmed, with the blocked reason shown until then. Per-member `ExportBar` downloads remain available the moment that member confirms; the archive is the one-action convenience, not a bypass of any member's gate. Archive format: **zip** (stdlib `zipfile`, per 11-RESEARCH Don't-Hand-Roll; entry names sanitized per Pitfall 7 — a UI-invisible constraint the planner inherits).

**No regression when N=1:** a group with a single member renders **without the tab strip and without the group export bar** — visually identical to today's Review plus the provenance line. The single-sheet path (CSV, one-sheet workbook, explicit `sheet=`) never enters the group flow at all (D-11-16) and is pixel-unchanged.

### 3. `__source_sheet` in Review: header metadata, never a row

**Decision:** the provenance column does **not** appear in `ReviewTable`. It is not a mapped field — it has no source column, no confidence, no amber state, and rendering it as a `FieldRow` would present a bookkeeping constant as something Claude proposed and the human must check (exactly the confusion D-11-12/13 exist to prevent). It surfaces in exactly two places: (1) the per-member header line — "sheet {name}" mono, beside the existing `upload {token} — {schema}` line, on every ingest including single-sheet (D-11-15: a traceability column that only sometimes exists is not a traceability column, and the same is true of its visibility); the tab label itself is the second rendering of the same fact in multi-member groups; (2) a one-line `Label/muted` note in `ExportBar` telling the curator the export will carry the reserved `__source_sheet` column — so the column's first appearance in a downloaded file is never a surprise.

### 4. Question ordering is total, so the panels never stack

Per 11-RESEARCH Pitfall 5 the order is: **sheet_question (Upload, workbook-level) → per-member structural_question → per-member date_question → per-member amber gate** — the first lives below the dropzone like its three siblings; the latter two live inside the member's Review tab. At most one panel is ever visible in any one place, preserving the existing "one panel at a time" rule without a new stacking mechanism.

## Screens & States

### 1. Upload — the sheet-question panel (NEW inline panel, 4th sibling)

**Layout:** unchanged screen (`max-w-[720px]`); the panel renders in the existing inline-question slot below `UploadDropzone`. `CardHeader`: `Layers` icon + "Choose sheets to ingest" (`text-heading`) + intro body line. `CardContent`: one per-sheet block per Discretion §1, stacked with lg 24px gaps. Footer: the submit `Button` (accent) with `Loader2` while submitting, and the blocked-reason line when disabled.

**States:**
- **Shown** — always, for `>1 worksheet` with no explicit sheet, regardless of coverage (D-11-06: no threshold exists).
- **Submitting** — CTA disabled + spinner; checkboxes and selects disabled; dropzone stays `locked` (existing idiom).
- **Error** — destructive `Alert` above the footer per Copywriting Contract; all selections preserved.
- **Headers-only** — identical: headers, row counts, coverage, and proposals all show (none is a cell value). No state difference to design.

### 2. Review — member tabs over N independent datasets

Per Discretion §2. States per tab: **question pending** (panel inside tab, amber dot on trigger) → **amber fields** (count badge) → **ready** (existing `ConfirmGate` ready tier) → **confirmed** (green check, `ExportBar` live). Group bar: **blocked** (reason line) → **ready** ("Download All"). N=1: no strip, no group bar. Sign-in gate, `ProfileAppliedBanner`, escalation line: all unchanged, now per member.

### 3. Everything else — unchanged

`Schemas`, `Documentation`, sign-in surfaces, `StructuralHintPanel`, `DateFormatQuestionPanel`, `ReconcilePanel` (still Upload-level for map-file conflicts), `ConfidenceChip`, `FieldRow`: untouched. The existing single-dataset Review path must render byte-identical when no group exists — this is a success criterion (SHEET-01 no-regression), not a nicety.

## Layout & Responsive Behavior

- The sheet panel shares Upload's `max-w-[720px]` container — no new width class. Header chips wrap; matched-pair lines stack; nothing scrolls horizontally.
- The Review member-tab strip sits inside Review's existing width, above the header block; with many sheets the `TabsList` wraps to a second line rather than scrolling (sheet names are short mono strings; wrapping keeps every member visible — a hidden member is a silently-forgotten dataset, which this phase exists to prevent).
- `ConfirmGate`'s 64px sticky footer is per active tab and its layout math is unchanged; the group export bar is a normal in-flow block above the strip, not a second sticky footer (two sticky footers would compete for the same edge).
- `AppShell` geometry unchanged; no new top-level tab.
