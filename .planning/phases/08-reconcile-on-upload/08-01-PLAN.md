<objective>
Build the reconcile CORE as pure service + domain logic, decides-never-renders (no HTTP, no printing): conflict detection between an uploaded map file and the master Schema, deterministic exact-alias pre-fill that seeds the existing mapper, and the `reconcile_or_map` / `apply_reconcile_resolution` orchestration that ties parse → (ask | augment) → pre-fill → Claude-fills-rest → merge → validate into ONE `MappingProposal` for the existing review flow.

This is the heart of Phase 08 (per 08-CONTEXT D-08-02, D-08-04). It REUSES Phase 07's `import_master_map` for the augment step and `Schema.from_master_map` to parse the uploaded map file — it does NOT introduce a second mapping engine; the alias pre-fill is a thin deterministic layer that short-circuits/seeds `resolve_table_mapping`.

Purpose: RECON-01 (map-file aliases augment the crosswalk before Claude maps) and the RECON-02 core (detect conflicts and refuse to silently pick a side) are proven at the service seam, independent of any route, so the API plan (08-02) is pure transport wiring.
Output: New domain types + service functions + a full pytest suite, all green.
</objective>
