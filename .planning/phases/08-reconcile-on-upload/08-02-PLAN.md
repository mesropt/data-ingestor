## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-06 | Elevation of privilege | augmenting the master crosswalk while signed-out/unverified | high | mitigate | The map-file branch enforces 401 (signed out) / 403 (unverified) inline before any augment; /api/reconcile/resolve depends on require_verified_user unconditionally (D-08-05) |
| T-08-07 | Denial of service | unbounded map-file / data-file upload | medium | mitigate | The map file is read under the existing _MAX_UPLOAD_BYTES bound; the data file reuses _write_bounded_temp_file (413 on overflow), no unbounded .read() |
| T-08-08 | Tampering | client forging the reconcile response / mislabeling provenance | high | mitigate | The route retains the real map_envelope/schema/vendor under the token; the human choices only pick a per-conflict side; provenance is server-resolved (entry.provenance), never a body field, matching confirm.py's WR-04 discipline |
| T-08-09 | Spoofing | client-supplied vendor label carrying authority | low | accept | vendor is a free-text source label with no authority (D-07-06 precedent); the alias provenance actor stays the server-resolved user on the confirm/augment path |
| T-08-10 | Information disclosure | retained temp file surviving after resolve/error | medium | mitigate | Every resolve branch (success + all error paths) unlinks the retained temp file via _unlink_ignoring_missing; the registry's LRU eviction still owns any orphan (state.py) |
