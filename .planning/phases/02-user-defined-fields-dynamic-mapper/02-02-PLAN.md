## Phase Goal

**As a** data curator, **I want to** turn an applied mapping into one normalised tidy table (decimal-comma fixed, units left exactly as declared), **so that** every export format later derives from a single trustworthy representation.

<objective>
Deliver EXPORT-01: the single canonical tidy form. Consume a `MappingProposal` + `RawTable` + `FieldSet` and assemble one row per record with columns = the user's field names, applying only the conversions the human authorised — decimal-comma driven by Phase 1's `column_locales` (D-14), dates only when a `date_format` was declared (D-13), units recorded but never converted (D-12). This is the one representation Phase 3's CSV/Excel/JSON writers and manifest will all build on (D-15).

Purpose: EXPORT-01 is the seam between "Claude proposed a mapping" and "we have clean records." Getting the never-guess conversion rules right here is what keeps the whole pipeline honest.
Output: `canonical.py` (pure converters + assembly), a CLI that prints the tidy table, and `tests/test_canonical.py`.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04 | Denial of Service | `canonical.assemble` per-row conversion | low | mitigate | Every conversion is wrapped per-value in `try/except ValueError` → flag; one malformed row can never abort the whole assembly (Pitfall 5). |
| T-02-05 | Tampering (silent data corruption) | unit / decimal normalisation | medium | mitigate | Units are recorded verbatim and never converted (D-12); decimal conversion fires only on a parser-confirmed `decimal_comma` column, never on `ambiguous`/`non_numeric` (D-14, Pitfall 4). Any doubt flags the field instead of writing a guessed value. |
| T-02-06 | Tampering | `strptime` on a field-set-supplied `date_format` | low | accept | `date_format` reaches only `datetime.strptime`, never `eval`/`exec`; single-user CLI, author is reviewer (RESEARCH Known Threat Patterns row 3). |
</threat_model>
