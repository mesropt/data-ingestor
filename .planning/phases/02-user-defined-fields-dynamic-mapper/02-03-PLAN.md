## Phase Goal

**As a** data curator in any domain, **I want to** load a shipped starter field-set preset (life-sciences, PK, or a non-biology one) as plain editable data, **so that** I can prove the tool has no built-in domain and adapt a preset instead of starting from scratch.

<objective>
Deliver FIELD-05: a starter library of three presets across domains, shipped as editable YAML data (D-20/D-21), plus the wheel packaging that makes them installable, plus the two synthetic corpus fixtures RESEARCH identified as gaps (European thousands+decimal, Excel-native date cell). The reagent-inventory preset exists specifically to be demonstrated: a field set from a neighbouring world (catalogue number, quantity, shelf, expiry) proves no biology is compiled into the mapper.

Purpose: FIELD-05 is the legibility proof for the whole pivot — presets that are provably data, not code, are what let a judge see the tool is universal. Sequenced last in the phase because the dynamic mapper (Plan 01) matters more if time runs short.
Output: `presets/pk-parameters.yaml`, `presets/reagent-inventory.yaml`, wheel packaging, two new synthetic fixtures, and `tests/test_presets.py`.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-07 | Tampering / Elevation of Privilege | preset YAML load | high | mitigate | Presets are loaded through the same `yaml.safe_load`-only loader as any field set (inherited from Plan 01, T-02-01) — an edited/malicious preset cannot construct arbitrary Python objects. |
| T-02-08 | Tampering | wheel packaging includes unintended files | low | mitigate | `force-include` maps only `presets/` explicitly; the `uv build` verification lists wheel contents to confirm exactly the preset YAMLs (and no stray files) are shipped. |
| T-02-09 | Spoofing (misleading demo data) | synthetic fixtures | low | accept | All fixtures are synthetic and deterministic (fixed RNG seed); no real/confidential vendor data enters the repo (competition rule, no-real-desktop-files rule). |
</threat_model>
