## Phase Goal

**As a** data curator, **I want to** declare my own target fields in a file and have Claude map any messy CRO export onto them, **so that** the tool works for my domain with no code change.

<objective>
Replace the four hardcoded-domain sites (D-19) with a user-supplied field-set model and a runtime-built structured-output schema, and wire it end-to-end so `--fields <path>` drives a real `propose_mapping()` call. This is the phase's core vertical slice: a field set on disk → runtime `Literal` schema → `MappingProposal` rendered by `cli.py`, with zero domain knowledge compiled into the mapper.

Purpose: FIELD-01/02/03/04 and MAP-01/02 all depend on the field-set model existing and the mapper being schema-driven. This plan is the load-bearing one — if time runs out after it, a working domain-independent mapper has shipped.
Output: `fields/` package (model + safe loader), `build_wire_models()` runtime schema, a domain-free `mapper.py`, an emptied `domain/models.py`, `reference.py` reborn as `presets/assay-potency.yaml`, a `--fields` CLI flag, exit code 5 (D-23), and a green test suite.
</objective>
