<objective>
Build the in-app Documentation page (DOCS-01): a static React content screen with a how-to and a glossary of the locked governed vocabulary, added as a second new tab in the existing shell so a curator learns the terms without leaving the app.

Per D-09-04 the content is pure React (no backend, no heavy markdown dependency — a simple component with the shipped tokens is exactly right). Two sections:
- How-to: the end-to-end flow — define fields (or load a preset) → upload (optionally attach a map file) → review yellow fields & resolve → confirm (signed in) → promote to a Schema → download/import the master map → reconcile a known vendor's next file. - Glossary: the four locked terms with the EXACT locked definitions — Schema, Field, Alias, and Organization (Organization marked *future / not yet in the app*).

Per D-09-01 it mounts as a Docs tab in the router-free shell. This plan shares App.tsx with 09-01 (both add a tab), so it runs in wave 2 after the Registry tab is wired.

Purpose: Teach the governed vocabulary in-context so the Registry's canonical↔alias↔provenance story is legible to a curator (and to judges).
Output: Documentation screen + Docs tab wired into the shell.
</objective>
