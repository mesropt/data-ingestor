<objective>
Deliver the Excel header-detection vertical slice: a workbook whose real header sits beneath banner/title/blank rows (zephyr_bio_ZB-2025.xlsx, header at raw row 4) is read structurally — the true header is located and a clean RawTable is produced end-to-end — and when the deterministic score cannot separate the header from a data row confidently, the tool returns a pre-filled StructureQuestion instead of guessing (D-03).

This introduces the openpyxl NORMAL-mode raw-grid reader (`grid.py`) that plans 03 and 04 also depend on.

Purpose: PARSE-01 is the single most consequential structural error class — shift the header by one row and every downstream field maps a shifted, clean-looking table that the "no yellow fields" gate cannot catch (D-02 rationale). Detecting the header structurally is the phase's core value.
Output: `structure/grid.py` (openpyxl normal-mode reader, native types), `structure/header.py` (width-consistency + type-mismatch scoring), and the Excel branch of `parse()`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted vendor workbook → openpyxl reader | An uploaded .xlsx is untrusted; a malformed or hostile workbook crosses into the openpyxl load path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05 | Denial of Service | grid.py load_workbook on a corrupt/chartsheet-bearing workbook | medium | mitigate | Iterate wb.worksheets (structurally excludes Chartsheet — D-17) so grid access never hands back a cell-less object that crashes; genuinely corrupt files raise the existing ValueError, uncertain structure returns a StructureQuestion (D-05). |
| T-01-06 | Tampering (of output) | header-row misdetection producing a shifted-but-clean table | high | mitigate | detect_header refuses to pick a header when the score margin is below the confidence threshold (D-03) and returns a StructureQuestion — the one structural-error class downstream gates cannot catch (D-02 rationale) is gated at the source. |

Note: XML entity-expansion (XXE) hardening for the openpyxl XML parser is tracked as T-01-01 and mitigated in plan 03 (defusedxml install), where the drawing/security surface is concentrated.
</threat_model>
