<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client cookie → deps.get_current_user | An attacker-controlled `di_session` cookie value crosses into the server; must be signature-verified, never trusted structurally |
| plaintext password → passwords.hash_password | Untrusted credential material enters the hashing seam; must never be logged or stored in the clear |
| package registry → uv install | Third-party code is added to the runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering | session cookie (auth/session.py) | high | mitigate | itsdangerous URLSafeTimedSerializer signature verification; read_session_token returns None on BadSignature — a forged/edited cookie never resolves to a user |
| T-06-02 | Information Disclosure | password handling (auth/passwords.py) | high | mitigate | Argon2id via pwdlib; only the hash is persisted; passwords.py imports no logger and never returns plaintext (grep gate in Task 3) |
| T-06-03 | Spoofing | replayed/expired session token | medium | mitigate | 14-day bounded max-age on the session token; expired tokens return None |
| T-06-04 | Elevation of Privilege | verification-token reuse as a session, or vice versa | medium | mitigate | Distinct itsdangerous salts for session vs verify tokens — a token minted for one use is rejected by the other reader (salt-isolation test) |
| T-06-05 | Denial of Service / misconfig | missing SESSION_SECRET | low | mitigate | Fail loud with RuntimeError at first use rather than signing with an insecure default (mirrors MissingCredentialsError) |
| T-06-SC | Tampering | uv installs (itsdangerous, pwdlib[argon2], authlib) | high | accept | Orchestrator pre-approved these overnight; 06-RESEARCH.md Package Legitimacy Audit confirms all four [SUS] flags stem only from the tool's absent download-stats source (Pallets / fastapi-users maintainer / pyca-adjacent projects with real GitHub repos), not a distrust signal — no human checkpoint per the spawning agent's explicit instruction |
</threat_model>
