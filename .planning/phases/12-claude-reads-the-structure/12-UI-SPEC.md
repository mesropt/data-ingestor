# Phase 12 — UI Design Contract

> Visual and interaction contract for the two — and only two — surfaces this phase touches: the **sheet-selection panel** (`SheetQuestionPanel`, Phase 11) gains a per-sheet layout verdict, and the **structural-hint panel** (`StructuralHintPanel`, Phase 4) becomes actually answerable for the first time (D-12-15: `answerable_by_hint=True`, because `hint.table_shape` finally has a reader). No new screens, no new primitives, no new installs, **zero new hex values, zero new type roles, zero new icons**. Generated by gsd-ui-researcher from `12-CONTEXT.md` (D-12-01..D-12-18), `12-RESEARCH.md` (§The Verdict Contract, §The New Call Site, Pitfall 7), `11-UI-SPEC.md` (binding, reused verbatim), and the components as built.

**Product principles this design must make LEGIBLE:**
- **Claude proposes, human disposes** — every verdict is a proposal; ticking a sheet IS the confirmation (D-12-02); nothing is un-pivoted until a human has had the chance to disagree.
- **Never guess silently** — `unknown` is a first-class state, not an error toast; it is what EVERY sheet shows when the model is unreachable (D-12-16), and the screen must be designed for that, not merely survive it.
- **The tool never presents a claim the human cannot check** — every verdict renders Claude's one-sentence `reasoning` and its `confidence` on the screen where it is confirmed. A cell value must NEVER render as a column header (D-12-12 — the live bug this phase kills).

## The Hard Design Question — How Much of the Verdict Is Editable (RESOLVED)

**Recommendation: accept/reject the KIND, plus the header-row affordance that already exists. No block-index editor in this phase.**

The verdict carries indices (`label_column`, `value_columns`, `first_row`, `last_row`, `header_row_index`, `first/last_data_row` — 12-RESEARCH §The Verdict Contract). The contract for what the human can do with them:

| The human CAN | Where | Mechanism |
|---|---|---|
| **Accept** any verdict | Sheet screen: ticking the sheet IS acceptance (D-12-02). Single-sheet: the pre-selected layout option + "Use This and Re-parse" | Existing (`SheetQuestionPanel.tsx:106-119`, `StructuralHintPanel.tsx:211-214`) |
| **Reject the kind and answer it themselves** | Sheet screen: per-sheet "answer it yourself" action → that member arrives in its Review tab showing `StructuralHintPanel` (the Phase 11 recursive-arm machinery, `11-UI-SPEC.md` Discretion §2, reused verbatim). Single-sheet: the layout options ARE the answer surface | One new per-sheet flag on the resolve payload (planner names it); the panel itself is reused, not duplicated |
| **Correct the header row** when answering "one row per record" | `StructuralHintPanel`'s existing header-row control — the number input (`StructuralHintPanel.tsx:141-155`) AND the clickable evidence-grid rows (`StructuralHintPanel.tsx:108-131`), pre-filled from `layout.header_row_index` | Existing, unchanged |
| **Skip the sheet** | Untick (multi-sheet); abandon the question (single-sheet) | Existing |

| The human CANNOT (say it out loud) | What happens instead |
|---|---|
| Edit `label_column` / `value_columns` / `first_row` / `last_row` (the key-value block indices) | If the labels shown look wrong (a value among the chips, a missing first label), the verdict is wrong and the human's move is **reject or skip** — the sheet is never ingested under an unconfirmed block map. It is skipped, never silently mis-read. |
| Edit `first_data_row` / `last_data_row` on a `row_per_record` verdict | Same: reject → answer "one row per record" with the header row; the data-row trim is Claude's to propose and the human's only to accept or refuse wholesale. |
| Answer "labels down the side" when NO key-value proposal exists (an `unknown` / `not_a_table` / refused verdict) | The option is **not offered** — a kind without indices is un-actionable (Python cannot un-pivot without the blocks, and the block editor is deferred). The honest copy says so (Copywriting Contract). |

**Justification against the principles.** A bare accept/reject fails "Claude proposes, human disposes" in the one confusion the redacted grid provably has (a two-column lookup table vs. a key-value sheet — 12-RESEARCH §Prompt Design item 3): the human MUST be able to say "no, ordinary table," and the header-row affordance completes that answer with zero new machinery. A full index editor fails the phase: it is a spreadsheet-region picker, real scope, and D-12-08 makes the human the ONLY check — so the check must stay *cheap*: read one sentence, scan the label chips, tick or reject. Everything the human needs to *detect* a wrong verdict is on screen (reasoning + confidence + the labels the verdict produces); everything they cannot *repair* fails closed to a skip or an unresolved question. "Never guess silently" is preserved end to end: no rejection path falls back to a guess.

## Discretion Calls (resolved here)

### 1. `layout` is a field on `SheetOut`, never a `status` member (12-RESEARCH Pitfall 7 — binding)

`SheetOut` (`frontend/src/lib/types.ts:225-231`) gains `layout: SheetLayoutOut | null` — `{ kind, confidence, reasoning, record_count, needs_confirmation }` is what the UI consumes (indices stay server-side; the browser never needs them, which is also the smallest possible untrusted-input surface). `status` (`types.ts:230`) keeps gate semantics. A `key_value` sheet is `status: "ok", layout.kind: "key_value"` — readable, tickable, with headers (its labels) and a Schema `Select`. The state-module derivations (`frontend/src/state/sheets.ts`) retarget accordingly:

- `isUnreadableShape` (`sheets.ts:67-69`) → true for `layout.kind ∈ {not_a_table, wide_matrix, multiple_tables}`; **NEVER for `key_value`** (the phase's point) and never for `unknown` (an unknown sheet is answerable, not unreadable — collapsing them would rebuild the dead end D-12-15 just killed).
- `UNREADABLE_SHAPE_LINE` (`sheets.ts:79-80`) → replaced by the per-kind refusal lines above (its "PARSE-V2-01, deliberately not v1" docstring is now history — rewrite it, don't strand it).
- `showsDetectedHeaders` (`sheets.ts:89-91`) → true for `key_value` (chips are the labels; caption "Detected labels").
- `showsSchemaSelect` (`sheets.ts:97-99`) → true for `key_value` and `unknown` (an unknown sheet the human ticks still needs its Schema chosen now — mapping runs after its layout question resolves); false for the unreadable kinds, as today.
- `_isPreTicked` (`sheets.ts:53-55`) → rule unchanged: `status === "ok"` + proposals exist. A `key_value` sheet with matched labels arrives ticked; an `unknown` sheet arrives unticked.
- `submitBlockedReason` (`sheets.ts:136-146`) → unchanged.

All layout-line variants (amber vs muted) key off the **server-sent** `needs_confirmation` flag, never a client-side confidence threshold — the same division as `FieldMapping.needs_confirmation`; the client renders gates, it does not set them.

### 2. Disagreement on the sheet screen routes to the ONE answer surface — it does not grow a second one

The per-sheet "Not right? Answer the layout yourself" action does not open an inline editor. It marks the sheet ask-me-instead in the resolve payload (one boolean per selection — planner names the wire field), and that member arrives in its Review tab showing `StructuralHintPanel` — exactly the Phase 11 recursive-arm shape (`11-UI-SPEC.md` Discretion §2: a member whose arm is still `structural_question` renders the panel inside its tab, `keepMounted`, `ReviewGroupTabs.tsx:280-285`). Rationale: an inline kind-select on the sheet card cannot complete the answer anyway (flipping key_value → row_per_record needs a header row, which needs the evidence grid), so an inline control would be a half-answer that still ends at the hint panel. One surface, upgraded once, reached from both paths. The action appears on **every judged sheet** — including a confident `row_per_record` — because under `headers_only` the judge is provably weakest exactly where a wrong `row_per_record` re-opens D-12-12, and the human is the only check (D-12-08).

### 3. The upgraded `StructuralHintPanel`: two options, one pre-selected, nothing invented

The panel keeps its title, its evidence grid, and its headers-only branch (`StructuralHintPanel.tsx:99-104` — still the only place the browser-side privacy guarantee for the preview is enforced; unchanged, leak noted in CONTEXT §deferred). Added, in order (md rhythm):

1. **Verdict block** — Claude's read per the Copywriting Contract, with the "Labels found" mono chips when the verdict is key-value. The chips are the human's checking material: `Patient Name, MRN, Accession #…` reading as field names IS the verdict being right; a `TAYLOR, James` among them IS it being wrong. This is how the curator checks without opening Excel.
2. **"How is this sheet laid out?"** — the `DateFormatQuestionPanel` two-option-button idiom (the multi-option/single-submit sibling `11-UI-SPEC.md` Discretion §1 already names as the family shape). "Labels down the side — {n} record(s)" appears **only when** the proposal carries key-value blocks, pre-selected when it does. "One row per record" is always offered; selecting it reveals the existing header-row control — the number `Input` (`StructuralHintPanel.tsx:141-155`) and the clickable grid rows (`:108-131`), pre-filled from `layout.header_row_index` when Claude proposed one.
3. **Submit** — the existing CTA (`:211-214`), disabled until an option is chosen, with the blocked line.

The `!answerable_by_hint` dead-end branch (`StructuralHintPanel.tsx:134-138`) becomes legacy: after D-12-15 every layout question arrives answerable. Keep the branch (a stale response must not crash), but no new copy is written for it.

Selecting "Labels down the side" submits **confirmation of Claude's blocks**, not new indices — the wire hint carries the layout verdict back (`StructuralHintIn`, `types.ts:476-482`, whose write-only `table_shape` field at `:482` this phase finally supersedes with `layout`). The human's row-click on the grid continues to set ONLY `header_row_index` — it never edits key-value blocks (the CANNOT table above).

### 4. `headers_only` and the labels — the ruling, stated so it can be argued with

A `key_value` sheet's labels are its dataset's **column names**, and column names show under headers-only — D-10-05's existing line, unchanged. They render as chips on both surfaces in both modes. Residual risk, acknowledged: before confirmation the labels are Claude's *claim* about which cells are names, and a wrong verdict under the redacted grid would surface values as chips — the same residual today's detected-headers rule carries, and the reason the disagree affordance exists on every sheet. The alternative (hiding labels under headers-only) would make the verdict uncheckable in exactly the mode where the judge is weakest — worse on both axes. The evidence GRID stays value-suppressed under headers-only as today (`StructuralHintPanel.tsx:99-104`).

## Screens & States

### 1. Upload — `SheetQuestionPanel` (extended, not restructured)

Per-sheet card anatomy (order unchanged from `11-UI-SPEC.md` Discretion §1, one insertion):
1. Selection row — checkbox + name + "{row_count} rows" + status/layout badge (`SheetQuestionPanel.tsx:106-119`).

### 2. Upload (single-sheet) & Review member tabs — `StructuralHintPanel` (upgraded once, reached from both)

Per Discretion §3. States: **key-value verdict** (verdict block + chips, key-value option pre-selected) · **other/unknown verdict** (verdict block or the couldn't-judge line; only "One row per record" offered + the honest limit line) · **row_per_record low-confidence** (verdict block; "One row per record" pre-selected with `header_row_index` pre-filled — the off-by-one fix path) · submitting · headers-only (grid suppressed, verdict/labels shown per Discretion §4). A confirmed key-value sheet reviews as an ordinary (often 1-row) dataset — downstream is 1-row-safe (12-RESEARCH §Down-stream), and its locale/date questions, if they fire, are the product working, not a bug (Pitfall 5).
