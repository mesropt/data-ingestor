<objective>
Collapse two pages into one. Delete **Define Fields**. Rename **Registry** → **Schemas**, and make it editable: one table per Schema, one row per canonical field, carrying both layers that already exist on `CanonicalField` — its constraints (what Define Fields edited) and its vendor aliases with provenance (what Registry showed). Both editable, behind the explicit edit endpoints Plan 04 built.

Then make sign-in required: Schemas / Upload / Review each render a shared interstitial while signed out (INGEST-06, D-10-13). Docs stays open — a prospective user reading what the tool does before creating an account is a deliberate exception, not an oversight.

Purpose: the product carried two competing notions of "the target fields." The Schema already holds everything Define Fields was editing (D-10-11) — deleting it loses no data, it was editing a duplicate concept.
Output: the Schemas screen and its three sub-components, the sign-in gate, the App shell surgery, the schema-edit API client, and four deleted files.

**This is an EXTENSION of the existing design system.** Every token, primitive, icon, and font already in `frontend/src/` is binding and reused verbatim. Zero new shadcn registry installs. Zero new hex values, type sizes, or spacing tokens. `10-UI-SPEC.md` is the contract; if something is not in it, it does not get built.
</objective>

| browser UI gate → server gate | The disabled-control tiers are a UX mirror; the real gate is `require_verified_user` on the endpoint |
