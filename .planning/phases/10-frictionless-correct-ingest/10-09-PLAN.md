**FastAPI dependency-override semantics (the reason the blast radius is what it is):** overriding `require_verified_user` does NOT satisfy a NEW `require_user` dependency — FastAPI resolves each dependency callable independently. Overriding `get_current_user` DOES satisfy both (`require_user` depends on it, and `require_verified_user` depends on `require_user`). This is why `tests/api/test_reconcile.py` (which overrides `get_current_user`) mostly survives while `test_confirm_dates.py` / `test_money_shot.py` / `test_confirm_gate.py` (which override `require_verified_user`) do not.

**`ProfileRow` has `UniqueConstraint("field_set_signature", "column_signature")`** (`persistence/models.py:77`), so `store.find(fs_sig, col_sig)` returns at most one row. A vendor recorded on the profile is therefore unambiguous *by construction* on the exact-signature path — ambiguity is only possible on the crosswalk fallback.

**Tests run the real alembic migration** (`tests/conftest.py:100-102` runs `command.upgrade(cfg, "head")`, deliberately not `create_all`). A new column REQUIRES a new migration, and the suite proves it. Latest revision: `8d7f8c21e1cd_soft_delete_canonical_field_and_alias.py`.
