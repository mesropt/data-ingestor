<objective>
Collapse Upload to the three controls it should always have had, and put the date question on screen.

Upload becomes: **Schema → optional map file → headers-only → dropzone.** Nothing else. The chosen Schema's canonical fields ARE the target fields, and the internal notion the code still calls a `FieldSet` never appears anywhere a user can see it (D-10-01/02).

Below the dropzone, a fourth inline question panel joins `StructuralHintPanel` and `ReconcilePanel`: `DateFormatQuestionPanel`, which asks the order of every ambiguous date column at once, with one submit, and applies each answer to every row of its column (D-10-07).

Review loses its redundant second Schema selector and gains a single Label/mono line reporting the escalation: how many fields Python matched from the crosswalk, and how many needed Claude.

Purpose: stop asking for what the tool can derive; stop guessing what it cannot. This is where a user finally sees both halves.
Output: three new components, two pure state modules, Upload and Review rewired, four deleted files.

**Quick task `260712-e0e` is REVERTED by this plan, not extended.** `FieldSetPicker`, its auto-select helpers (`pickDefaultTemplateId` / `readLastTemplateId` / `writeLastTemplateId`) and its `submitBlockedReason` are **deleted outright**. `SchemaPicker` is a fresh, simple, un-auto-selecting `Select` — the user always picks explicitly. Carry forward no last-used persistence and no auto-pick-if-only-one-exists logic; if a future phase wants that convenience back it is a new, deliberate decision against the new picker, not an inherited behavior (UI-SPEC Discretion §5).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `POST /api/date-format/resolve` | The client answers a safety-critical question about how to interpret every date in a file |
| server → date panel (`headers_only` on) | Cell values must not cross into the browser when the toggle is on |
| mapping response text (reasoning, validator_note, source columns) → React render | Model- and file-derived text rendered into the DOM |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-31 | Tampering | `toResolvePayload` / `DateFormatChoice` | critical | mitigate | A client sending a fabricated strptime format to flip every date. The payload structurally carries only an ORDER; there is no format field on the type at all, and Plan 05's `DateFormatChoiceIn` has none either, so the server would ignore one anyway. Defence in depth on both sides of the wire. Pinned by an explicit key-shape assertion in `dateFormat.test.ts`. |
| T-10-32 | Information Disclosure | `DateFormatQuestionPanel` under `headers_only` | high | mitigate | Cell values reaching the browser through a NEW panel that the existing headers-only rules never covered. Two layers: the server strips `example_values` in the wire layer (Plan 05, tested), AND the panel omits previews under `headersOnly` (this plan, human-verified in checkpoint step 3). Neither layer alone is trusted. |
| T-10-33 | Tampering (XSS) | `DateFormatQuestionPanel`, Review's escalation line | medium | mitigate | `source_column` and `example_values` are untrusted file-derived text. React escapes by default; `escalationLine` returns a plain string built from integers, never markup. `dangerouslySetInnerHTML` appears nowhere. |
