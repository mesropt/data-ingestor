<objective>
Wire the escalation. Three things land in the service layer, all pure-Python and all testable without an API key:

1. **Python → Claude → human (INGEST-02, D-10-03).** A deterministic alias-crosswalk pre-fill runs before any LLM call; Claude sees only what Python could not resolve; the existing amber gate still catches what Claude could not resolve confidently.
2. **Date normalization (INGEST-04, D-10-04..08).** The detector from Plan 01 runs on every date-typed mapped column, always — even when the field declares a `date_format`, because a declared format is a human claim to be checked, not trusted.
3. **The Schema→FieldSet adapter.** The Schema's canonical fields ARE the target fields (D-10-02).

Purpose: this is where the two dangerous things in this phase actually bite. A declared format that parses every row and is still the wrong order must flag. A tombstoned field must not resurrect. Both get explicit, named tests here.
Output: an extended `canonical.assemble`/`validate`, a new `service.resolve_date_formats`, a new `service` Python-first pre-fill, `field_set_from_schema`, and three new test files.

**No HTTP, no UI in this plan.** Everything here is called by Plans 04/05.

|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-10 | Tampering | `resolve_date_formats` | critical | mitigate | A silently-wrong date order flips every date in an exported file. Fail closed: AMBIGUOUS with no declaration raises a question, never a guess. A declared format contradicted by the column's own evidence flags rather than converts. `UnresolvedDateColumnsError` blocks any attempt to proceed with an unanswered ambiguous column. |
| T-10-11 | Information Disclosure | date detection vs `headers_only` | high | mitigate | Detection reads real cell values server-side. It must not become a leak. Structurally safe: it makes no outbound call, and `mapper._render_table` remains the only send site. Pinned by `test_date_detection_is_identical_under_headers_only`, which asserts BOTH that detection is unchanged AND that the captured outbound request carries no cell value. |
| T-10-12 | Spoofing | `_vendor_agnostic_alias_index` | medium | mitigate | A crosswalk poisoned by one vendor's alias could hijack another vendor's column at confidence 1.0 with `needs_confirmation=False` — no human review. Mitigation: a normalized header mapping to two DIFFERENT canonical fields across vendors resolves to `None` (collision) and falls through to Claude. Never guess which vendor is right. |
| T-10-13 | Tampering | tombstone read paths | high | mitigate | A missed filter resurrects a deleted field/alias. Mitigated structurally in Plan 02 (all four store queries filter), and re-verified here against the two paths this plan owns: `field_set_from_schema` (the mapper's target field list) and `_vendor_agnostic_alias_index` (the Python-first match). Each has a dedicated tombstone test. |
| T-10-14 | Elevation of Privilege | pre-fill confidence 1.0 | medium | accept | A pre-filled mapping is `needs_confirmation=False` and skips the amber gate. Accepted: an exact alias match against the *governed* crosswalk is a prior human decision (ALIAS-03 provenance), and `validate()` still runs over every pre-filled field's values against its declared constraints (D-03) — a crosswalk match never exempts a value from a constraint check. |
| T-10-SC | Tampering | npm/pip/cargo installs | high | mitigate | **This plan installs ZERO new packages.** No package-legitimacy checkpoint is required because no install task exists. |
</threat_model>

<success_criteria>
- Python → Claude → human escalates in that order; a fully-crosswalked file spends zero LLM calls; a partially-crosswalked one sends Claude only the uncovered fields.
- The existing profile auto-apply still short-circuits both — it is not weakened.
- Every date-typed mapped column is classified, always, even when a `date_format` is declared.
- A declared format that parses every row cleanly and still implies the wrong order flags the field amber with an actionable note.
- An ambiguous column with no declaration produces a `DateFormatQuestion` and no mapping.
- Date detection is bit-identical under `headers_only`, and no cell value reaches the outbound request.
- The Schema-derived FieldSet's signature matches the promoted one's, so existing learned profiles keep matching.
- Tombstoned fields and aliases are invisible to both the target-field list and the alias index.
</success_criteria>
