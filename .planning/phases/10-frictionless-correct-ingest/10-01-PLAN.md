<objective>
Build the pure, dependency-free date-order classifier that INGEST-04 rests on, and the two domain types that carry its unresolvable case to a human. No wiring, no service changes, no HTTP — this plan produces a classifier and a question shape, both testable without a database or an API key.

This is the structural sibling of `parsing/structure/locale.py` (the decimal-comma ambiguity predicate). Mirror its shape: a pure classifier module, an explicit ambiguity predicate, an enum of outcomes, and a resolve-with-the-human's-answer function.

Purpose: `strptime("03/04/2025", "%m/%d/%Y")` does not raise even when the value is genuinely 3 April. Catching parse failures is not enough. This module produces *independent evidence* about a column's true order so a declared format can be checked rather than trusted (D-10-06), and so a genuinely ambiguous column can fail closed to a human question (D-10-07).
Output: `parsing/structure/date_order.py`, `DateFormatConflict`/`DateFormatQuestion` in `domain/models.py`, full unit test coverage against the repo's real fixtures.
</objective>

  <action>
    Create `src/assayingest/parsing/structure/date_order.py` implementing exactly the surface Task 1's tests pin.

    Design constraints (non-negotiable — these are what make it correct):

    1. **Evidence, never a heuristic.** The order is proven by a component > 12 somewhere in the column, or it is AMBIGUOUS. There is no "most CROs use MM/DD" fallback anywhere in this file (10-RESEARCH.md Anti-Patterns).

    2. **Explicit candidate-format list + `datetime.strptime`. Do NOT use `dateutil`.** `dateutil.parser` guesses an order by design — that is precisely the failure mode this requirement exists to eliminate. It is present transitively via pandas; it must not be imported here or added to `pyproject.toml`.

    3. **The candidate list must include the Excel-native shape `%Y-%m-%d %H:%M:%S`** as a first-class member, not an afterthought. Both the openpyxl-direct path and the legacy pandas `dtype=str` path turn a date-formatted cell into that exact string.

    4. **Excel serials use `openpyxl.utils.datetime.from_excel`**, never a hand-rolled `date(1899,12,30) + timedelta(days=n)`. `openpyxl` already encodes the Lotus 1-2-3 leap-year-bug compensation correctly. Apply a defensive plausible-date range (roughly 1970–2100) and return `None` outside it; document the standard-1900-epoch assumption in the docstring as a known limitation (a 1904-epoch Mac workbook would be ~4 years off, and `RawTable` carries no workbook epoch).

    Implementation shape:
      - Derive a small set of separator/width-parameterised templates rather than hardcoding a long list: for each separator in `/ - .`, for each year-width (`%Y`, `%y`), for each optional time suffix (`""`, `" %H:%M"`, `" %H:%M:%S"`), the day-first and month-first templates are `%d{sep}%m{year}{time}` and `%m{sep}%d{year}{time}`. ISO templates are `%Y{sep}%m{sep}%d{time}` plus the bare `%Y%m%d`.
      - Classification: scan the column's non-blank values. Determine the shared shape (separator, year width, time suffix) from the values. Extract the two leading numeric components. Then: any first component > 12 AND any second component > 12 in the SAME value → INVALID; any first > 12 → DAY_FIRST; any second > 12 → MONTH_FIRST; ISO-shaped (4-digit leading year, or bare 8 digits) → ISO; all bare integers in the Excel-serial range → EXCEL_SERIAL; nothing date-shaped → NON_DATE; otherwise → AMBIGUOUS with both candidates populated.
      - The resolved `date_format` for a proven order must be validated by actually `strptime`-ing every value with it before it is returned. If it does not parse every value, the column is not confidently that format — degrade to INVALID rather than returning a format that will fail at conversion time.
      - `example_values` carries at most the first 3 non-blank raw values.

    Follow the project conventions: module docstring explaining the *why*, single level of abstraction per function, type hints everywhere, error messages naming the consequence, `str | None` union syntax.
  </action>
