# Quick Task 260712-c47: Mint verification token before persisting the user Summary

**Reordered `signup()` so `create_verification_token(user.id)` runs before `store.save(user)`, turning a token-mint failure (e.g. unset `SESSION_SECRET`) from a corrupting failure (persisted, unverifiable, un-retryable account behind a 409) into a clean no-op (nothing written, email stays retryable).**

## Decisions Made
- Token minting moved ahead of `store.save`; `verify_url`/log stay after the save (unchanged happy path).
- No try/except introduced — the `RuntimeError` from `create_verification_token` keeps propagating (log-or-raise convention; the exception already names its own consequence).
- Test restoration uses `monkeypatch.setattr` back to the real function, not `monkeypatch.undo()`, to avoid also clearing the `SESSION_SECRET` env var `_client()` set for the same test.
